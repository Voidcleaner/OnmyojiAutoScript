# BeginnerQuest（试验性新手主线任务）

放在 OAS 的 Script 设置菜单中，默认关闭。可以单独运行 `Script("账号配置").run("BeginnerQuest")`，或启用对应任务调度。请从已经登录的庭院或剧情场景开始；本任务不替代账号验证。

## 已实现并实测的流程

- 庭院/剧情场景的 NPC 三点对话图标（含右边缘被裁切的图标）。
- 对话中的跳过、探查眼睛、怪物问号、剧情战斗入口。
- 识别自动战斗状态等待结算、点击屏幕继续、领取奖励与升级功能提示。
- 第一个 CrossOver 实例从4级推进到7级；完成“屋前的调查”和凤凰林后续剧情，解锁神乐。

另支持右上角 `>│` 动画跳过符号的几何检测，已通过合成图测试，并在当前剧情实测完成动画跳过与确认。

规则采用 `rules.json` 的模板＋区域＋阈值和 OCR 按钮白名单。只对已识别的对象操作；不会把顶部滚动聊天中的关键词当作任务按钮。

## 屏幕外 NPC 搜索

参考困难探索的背景拖动与画面变化比较：未发现交互目标、已确认剧情场景 HUD 且场景中没有对话/菜单文字时，等待3秒后按住背景向左拖动查找。每次移动后重新识别 NPC、探查和战斗图标；目标优先于继续搜索。连续两次背景无明显位移时反向，背景动画持续变化时也会预留反向搜索预算，再遇边界或达到 `max_search_swipes` 后保存现场并停止。未知界面不拖动。

默认 `search_npc=true`、每轮最多8次拖动，搜索也计入任务动作和总时长上限。拖动路径在探索背景安全区域小幅变化；点击中心默认±2像素（可设0关闭），动作后等待0.9—1.5秒。这些变化用于界面容差和动画等待，不能保证避免游戏账号处罚。当前 HUD 模板针对已实测的新手剧情场景，其他场景需要补充准确的 `search_scene` 规则。

## 借用与队伍：当前实测范围

`borrowing.BorrowingAdapter.borrow("麓铭大岳丸")` 可通过珍旅居进入唤妖借处，核对同名卡牌的“使用中”状态。三个借用槽全部占用时不会自动替换其他借用；返回的 `on_field_verified` 为 false，借到式神不代表已上阵。

当前账号实测在御魂准备界面按住0.8秒再拖动，用麓铭大岳丸替换原借用姑获鸟；游戏限制同时上阵一个借用式神。模板同时检查麓铭大岳丸/座敷童子的卡牌与对应位置的上阵标记，排除只选中卡牌的情况。该阵容已通关御魂六层和七层。

`require_verified_team` 默认开启。现有上阵模板仅针对本次校准的麓铭大岳丸、座敷童子及当前卡牌布局；借用槽导航、任意式神自动编队和其他账号布局仍需继续验证，不能宣称已有通用自动配装/编队能力。

## 边界与停止条件

- 默认每次最多80次动作、600秒、10次战斗入口/准备动作；均可配置。
- 未识别画面等待30秒后保存到 `log/beginner_quest/<配置名>/unrecognized.png` 并退出。
- 同一位置同一种动作连续无进展时退出；已识别资源不足、账号登录或战败提示时退出。
- 运行上限只是本轮结束，不代表整条新手主线通关。
- 使用本任务自己的动作/时长上限，避免通用双按钮循环保护误伤连续的“NPC对话—跳过”。
- 不主动购买体力、抽卡、升级、销毁物品。个性化推荐弹窗选择关闭推荐。

## 配置

`beginner_quest.quest_options` 提供 `target_player_level`（默认40）、`max_actions`、`max_seconds`、`idle_seconds`、`max_battles`、`borrow_support`、`preferred_support`、`fire_provider`、`require_verified_team`、`search_npc`、`max_search_swipes`、`click_jitter`、`dry_run`。
`dry_run` 只识别一个可用动作，不发送点击。

测试：项目根目录执行 `python -m unittest discover -s tests -p test_beginner_quest.py`。

战斗准备后会记录等待结算状态，重启可恢复；仅点击已识别的结算按钮，不把战斗特效当作 NPC。跳过确认弹窗也支持跨进程恢复。

角色介绍页采用上下两个固定装饰边框共同识别，可关闭尚未单独录入的角色介绍；亮光必须结合具体界面和交互标记判断，不将普通发光场景装饰作为点击目标。

## 现有模块复用与40级路线

详见 [任务路线、来源及验证边界](../../docs/newbie-route.md)。`planner.py` 可把实际任务要求转换为 `Orochi`、`Exploration`、`ExperienceYoukai`、`Tako` 的短批次调用；它与剧情识别配合，不把社区攻略当作完成凭据。组队任务须有队友连续停留3–5秒，超时不单人开战；战败会停止该批次，先评估阵容与御魂。40级目标仍在实测推进中，不能宣称已有全程无人值守通关能力。

庭院中会定期读取主角头像等级，达到目标等级结束本轮；剧情中的探查、战斗与任务图标优先于 NPC 三点图标。`novice_hub.py` 可读取缘初手札任务并领取已完成的免费奖励，再交给路线规划器选择后续模块；尚未覆盖的任务会保留待处理。

`awakening.AwakeningAdapter(config, device).run_to(5)` 复用 OAS 导航和通用战斗，按锁定图标选择已解锁的前置层，单批最多5场，首败停止；当前标定范围为1–5层，列表外目标不会盲滑选择。

`ExplorationHardAdapter` 在启动和每次重开章节时核验困难选中状态，复用原有探索战斗。新手御魂1–5层也使用锁定与选中检查，避免点了锁定层却继续挑战旧层；完成后仍需手札核验。

新版式神录标题也可用于导航；未入寮弹窗会取消，并在当前导航会话中避开需要入寮的结界突破入口。外观奖励的“是否立即启用”弹窗会取消，不阻塞后续领取。

`soul_upgrade.SoulUpgradeAdapter.finish_preview()` 仅负责已核验的0→3级强化预览：要求单个四星青吉鬼的8750经验、目标3级、金币消耗不高于14000。只提交一次并核验结果；当前尚未提供任意御魂自动选择和更高等级强化，不应将其当作完整配装模块。

`training.TrainingAdapter.commit_preview()` 可核验已选好的经验达摩类型、等级、空余材料槽、前后等级与金币上限，只提交一次升级；结果页需要读到实际等级变化才关闭。已实测山兔20→25级（13级蓝达摩＋1级红达摩）。素材导航/自动选择仍需单独适配，当前不能宣称任意式神全自动养成。

新手副本战败会在关闭结算前记录到本地 `failures.json`。同一 `build_revision` 不再挑战失败层；只有阵容确实改变后，调用者才应传入新的版本标识。

`leveling.LevelingRunner(config, device).run_to(chapter=10, target=40, max_batches=30, min_stamina=60)` 会明确核对普通难度与章节，只刷经验UP怪，复用原探索模块。每批读取主角等级和体力，达到目标、体力不足、识别失败或战败即停止，状态保存在本地 `leveling.json`，不购买体力。此流程仍需持续实测，尚未验证完整达到40级。

练级循环默认连续3批主角等级不变即返回 `replan_needed`，避免把低级经验怪无限重复刷到资源耗尽。`first_clears.FirstClearRunner.run_route()` 支持按普通/困难章节顺序复用探索，只有实际首领胜利才写入通关记录；30级节点会返回重新规划状态，不能当作40级完成。

`story.StoryRunner(config, device).run_chapter(chapter)` 将剧情作为可复用短批次：先读取新手任务，只点击与目标章节对应的“前往”，复用剧情交互/跳过/准备战斗识别，结束后重新读取任务和主角等级。任务仍在则返回 `replan_needed`；未知画面或战败会保存现场并停止。无章节参数时仅从庭院识别 NPC 推进，不猜测入口。规划器会优先处理明确的故事/剧情要求，再安排重复练级。当前角色已实测30级；庭院模式已实测自动进入剧情、连续对话跳过、战斗准备及结算继续；按章节任务行进入仍待实测，不代表已达到40级。批次结束若仍在战斗，会返回 `resume_battle`，下次直接续战，不打开任务菜单打断战斗。

经验妖怪与石距建队前会读取对应副本列表行上的倒计时；识别到冷却则返回 `{'status':'cooldown','retry_after_seconds':秒数}`，不重复点击创建队伍。未识别倒计时不代表有剩余次数，后续仍需实际建队确认。

庭院剧情入口出现 `Lv:31` 等标签时会结束剧情批次并请求练级；实际已用普通十三章从30级升到31级，再继续庭院剧情。新手探索在关闭自动候补时保持队伍，不再反复点击候补开关。达到目标等级后，即使升级功能提示遮住体力数字，也会停止练级，不额外开战。

新手探索的“全部怪物”模式采用有上限的双向搜索；桌面模式按住0.8秒再拖动，避免背景变化较小就误判右边界。已实测修复困难第十六章提前退出问题，并核验首领获胜。练级状态同时记录头像经验条比例，等级未变但经验持续增长时不会误判停滞。

`LevelingRunner.run_to(..., difficulty='hard', xp_only=False)` 可选择已核验的困难章节练级；默认仍为普通难度。状态中记录难度、主角等级、经验条比例和体力，用实际批次结果比较收益。当前已实测困难十六章练级，仍保留首败、资源下限与停滞停止条件。

探索首领图标靠近顶部聊天横幅时，改点圆形按钮下部，避免打开聊天。必须确认进入战斗/准备画面才调用通用战斗等待；20秒内未确认则停止，不把按钮消失当作开战。已打开的世界聊天侧栏仅在频道标题与发送按钮同时出现时折叠，不输入或发送内容。此修复已实测首领获胜并返回庭院。

体力读取兼容溢出时的 `126+` 和低于容量时的 `92/100`，后者只取当前值92。庭院实测33级，已解锁困难十七章，下一剧情门槛35级；尚未验证达到40级。练级停滞判断同时检查经验条增长。

复用“练级到剧情门槛→继续剧情”可调用：

```python
from tasks.BeginnerQuest.progression import run_level_gate
result = run_level_gate(config, device, chapter=17, target=35)
```

只在实际等级达到目标后启动有时限的庭院剧情；体力不足直接返回，不购买资源。剧情结束返回重新规划或续战状态，不将中间等级或剧情批次当作40级完成。异常继续沿用原脚本的停止与现场记录机制。
